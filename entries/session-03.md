# Session 03: Personal website v0

**Date:** 2026-11-21

## What I built

- Built and launched version 0 of my personal website at [taresa.github.io](https://taresa.github.io), the page that replaces LinkedIn as my professional presence.
- Published the code to GitHub at [Taresa/taresa.github.io](https://github.com/Taresa/taresa.github.io).
- Set my global git identity to my GitHub no-reply address.

## What I learned

- A good brief to Claude Code has four parts: the goal, the audience, the constraints, and the content. Giving all four up front meant fewer rounds of correction.
- Plan mode lets me approve the approach before any files change. Reviewing the plan was cheaper than reviewing a finished page I'd have to undo.
- Reviewing the diffs before approving them caught details I'd have missed, and kept me in charge of what actually goes on the page.
- Starting Claude from my projects folder lets it see my other repos and the source files next to the new one.
- Committing locally and pushing publicly are two separate decisions. A local commit is private and easy to change, and a push puts the work on GitHub where anyone can see it.
- Git needs to know who I am before it will commit. I set my identity to my no-reply address so my personal email stays out of the public history.

## What I'd do differently

- Set up my git identity before the first commit instead of hitting the error mid-task.
- Check each prompt for unfilled placeholders before sending it. One request still said "[paste intro above]" with no text, so that change had to wait.
- Update the page title and meta description whenever I change the headline or intro, so they don't drift out of sync.
